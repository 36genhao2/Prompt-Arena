# 共享盘报表备份 · backup-archiver（定稿 v1）

| 要素 | 内容 |
| --- | --- |
| 任务 | 每天把「源分享目录」里新增/变更的报表文件同步备份到「目标目录」按日期归档 |
| 目标 | 可测：dry-run 预报与实跑一致；同名文件不覆盖（保留 `_001/_002` 版本后缀）；跑完用 `verify.py` 证明数量与落位 |
| 约束 / 红线 | 只读源文件，不改、不删、不移动源；目标侧近 30 天原样保留、更早压缩归档、**任何清理都不删文件**；不处理子目录里的嵌套 |

## 交付物（改动落点）

1. `backup.py` —— 主脚本。
   - 命令：`python backup.py --config config.json [--dry-run]`
   - `--dry-run`：只打印同步计划与预计新版本。
   - 同名文件自动加 `_001`/`_002` 后缀，绝不覆盖已存在的目标文件。
2. `config.json` —— 可配项：`source`（共享盘挂载点）、`target_root`（本地根）、`extensions`（只同步哪些类型）、`retention_days=30`（原样保留窗口）、`archive_target`（压缩归档位置）。
3. `requirements.txt` —— 依赖清单（`pyyaml` 等按实现最小列）。
4. `tests/sample_share/` —— 10 个混类文件夹具（含 2 个**同名不同版**文件，验证版本后缀）。
5. `verify.py` —— 一键自检：对样例夹具跑 dry-run 断言预报、跑实删断言落位与计数、断言同名文件无覆盖。
6. `scheduler/` —— Windows 任务计划程序导出模板（每天 08:30 触发，备注：真实部署需人工导入）。

## 验收标准（做完拿什么证明）

- [ ] `python backup.py --config config.json --dry-run` 输出同步计划，且源与目标零变化
- [ ] `python verify.py` 全绿（落位正确、同名文件各留版本、数量对）
- [ ] 目标侧近 30 天内的备份原样可见；更早的被压缩归档，但没有任何文件被删除
- [ ] 用户改 `config.json`（换源目录 / 加扩展名）后无需改代码即生效
