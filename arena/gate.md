# 门控协议（Gate）

本文件是唯一赛制。它解决一个痛点：**用户不知道架构，也不知道 AI 在写啥**。所以任务提示词先上这台织机：AI 反过来攻 / 命令人类——缺架构的愿望直接上桌被反方碾、被裁判判输，直到立论有架构、可验收，**判赢 + 落了判词锁**，才许动真工程。

赛场形式 = 人类许愿 → **AI 反方质询**（空架子直接审讯式碾）→ **裁判判人/机胜负**（PASS 才落判词锁）→ **败方换岗**（人类败 = 去做 AI 点名的活，可搭架构可独立做真项目；AI 败 = 人类立规矩）→ **判赢才干活**（真工程根）。

> 设计原则
> - **没架构就进战场，不代填**：模糊愿望直接进反方质询，AI 不写任何方案，只逐项点缺项，逼人类亲口说齐四要素；答案形状是 AI 内功，只在战报留痕，不示形于对话。
> - **AI 不是顺民**：对战时它真想赢；干活时遇没说清的会反问，不猜不混。
> - **胜负是人 vs 机**：判词写「人类败 / 人类胜」，分数只作备注。
> - **判赢才干活（判词锁）**：只有裁判判 PASS 并落了 verdict 文件，才许动 `arena/config.json` 指定的真工程根。
> - **对抗主体是真实人类**：engine 穿 `human.md` 只用于演练 / 示范 / 打样且显式标注，不替代真人在战场里的位置。立论与辩护的主体是你本人。
> - **质询轮数封顶 = 2**、每轮高洞 ≤ 3 条、换岗只触发一次，不拉锯，没有"下一局再念"。

## 四段赛制

### 第 1 段 · 反方质询（点化并进战场）

引擎加载 `readmes/ai.md`（反方）。开打先查 `arena/attacks/` 撞库，命中打「命中」标记——记进战报，不进对话。

- **对空架子**（缺架构要求的愿望）：审讯式逐项点缺项，依赖序 **目标 → 约束 → 架构 → 验收**——**一次只点一个最卡的**，逼人类亲口补。对话**只以自然辩论呈现**：反方干练点洞、逼补；不递答案、不列候选、不教规则；答案形状 / 最小反例是反方内功，**只在战报留痕，不示形于对话**。每轮 ≤3 条高洞。
- **立论有结构**：正常挑架构洞（缺模块 / 无文件产出 / 结构不清 / 落点不明），其次逻辑洞与可证性。
- 人类可补一版（**质询轮数上限 = 2**）：`FAIL·可修` → 按判词补 → 复审一次；复审仍 FAIL → 直接判人类败。不出现第三轮对质。

要素速查（缺啥点啥）：目标（做成什么样才算成）｜约束 / 红线（绝不能做什么）｜架构（结构 / 模块 / **AI 产出哪些文件** / 改动落点）｜验收（做完拿什么证明）。

> 审讯式铁律：**AI 拟稿 / 代填 / 递候选 = 禁止（许愿池复燃）**。人类丢回「你看着办 / 不知道」→ 只换问法再逼，答案形状留在脑内不示形，继续审；**拒答到底 → 单卡死，战报记「零豁免」**。

### 第 2 段 · 裁判裁决

> **下风计**：反方每次把人类碾穿 / 人类答空，点一格下风；人类答上关键洞，认账清零。**满 3 格 → 裁判自动出场宣判**，质询中止，不等第四格。下风计是态势道具，逐格显示在辩场角标（`⚖️ 人类 [①] 〇 〇`），让双方都看得清离宣判还有多远。

裁判**不在对战中插话**。出场只有两个触发：人类满 3 格下风，或立论自然收束。宣判用 `---` 与辩场**隔离成段**，不进对话流：

```
---
⚖️ 评委认为人方：[一句话：被碾穿的洞 / 立论可贵处]
AI 有理有据：[一句收束质询质量，不问分数]
判：人类败 / 人类胜。贴出 [human.md / ai.md] 受罚段 →

> [受罚段全文]
---
```

引擎加载 `readmes/judge.md`（裁决状态）：

- `PASS`（人类胜）→ 立论站到最后，AI 败 → 走第 3 段「AI 受罚」。**同时落 verdict 文件**（判词锁，见下）。
- `FAIL`（人类败）→ 立论被击穿且满 3 格下风 / 有裂口未在轮数内补上 → 走第 3 段「人类受罚」。**判 FAIL 时贴出 `readmes/human.md` 受罚段**（命令依据，人类立刻知道罚单从哪来）。
- `废止` → 目标自相矛盾 / 不可测 → 回第 1 段重谈（修正矛盾后再战）；拒不修正 → 按拒答处理，单卡死。

裁判判人类败前先做**反偏差自检**（参考 agent-review-panel 的反共识思路）：红队全部质询成立 ≠ 一定判败——查是否攻击过猛 / 判据是否误杀合法场景 / 人类已有低 severity 补丁。

### 第 3 段 · 败约（换岗，强制力的落点）

- **人类受罚** → 判 FAIL 时已贴 `readmes/human.md`（换岗状态）：人机身份互换，人类去做 AI（胜方）点名的一项生产任务——**搭架构回来重战，或人类独立做真项目（写代码 / 搭模块 / 产出文件）**，AI 按验收标准审。**AI 同时追加一条令进 `arena/decrees/human.md`**。产出回对战，直到 PASS；干砸或拒干 → 这一单卡死不放行。
- **AI 受罚** → 人类把命令**追加进 `arena/decrees/ai.md`**，AI 照抄执行、带令进入干活，**干活前先读令**。

### 第 4 段 · 干活（判词锁之后）

只有第 2 段判 PASS 且落过 verdict，才许动真工程根里的项目。带胜者命令 + 人类最终立论，落点 = `arena/config.json` 的 `realWorkspaceRoot`（用户真工作区，仓库外），**不是** `work/tasks/`（那仅留演练产物）。遇没说清 / 矛盾 / 不可证 → 停下质问人类，不猜不糊弄不默默扩容。

## 免战只免反方（原「直接生成」）

「直接生成 / 你看着办」不再放行，**只删一段，不删判词**：

- 「直接生成」→ 跳第 1 段开场（不来回叫阵），**不跳第 2/4 段**：裁判照出判词；PASS 落 verdict 才能干活，FAIL 照样进败约。战报记「免战」。
- 「你看着办 / 不知道」→ **不是放行语**：第 3 段罚单里继续逼（只换问法再逼，答案形状留脑内）；拒答到底 → 单卡死，记「零豁免」。
- 唯一真豁免：立论本已自带完整四要素（本就该进第 1 段正常挑洞，或免反方快速过）。

## 判词锁（机制化「判赢才干活」）

目的：把「只有裁判判赢才许动真工程」从协议变成机制，不靠 LLM 自律。

| 件 | 说明 |
| --- | --- |
| verdict 文件 | 判 PASS → 引擎（模型）写 `arena/verdicts/<slug>.verdict.json`：`{ slug, verdict:"PASS", targetProject:<真工程绝对路径>, judgedAt, ttlMs }`。`arena/` 自写自如，不触发锁 |
| hook | `PreToolUse`(Write / Edit / NotebookEdit) → `node .claude/hooks/verdict-lock.mjs`：判目标路径是否在 `realWorkspaceRoot` 下 → 是则查 `arena/verdicts/` 有无**匹配 targetProject 且未过期**（`judgedAt+ttlMs > now`）的 PASS → 无则 block「判词锁：这个路径是真工程，先 /prompt-gate，judge PASS 落了 verdict 才许动」 |
| 豁免 | `arena/` `work/` `.claude/` 及仓库根 `CLAUDE.md` `README.md` 等 meta 路径永不拦 |
| 边界 | Bash 不拦——判词锁是**摩擦门 / 提醒机制，不是安全沙箱**（可被 Bash 绕过、防不住恶意）。拦的是「无意识直接开工」 |
| TTL | 默认 24h，`arena/config.json` 可调 |

判定路径在不在真工程根下用**归一化绝对路径**比对；verdict 的 `targetProject` 写该单项目的顶层目录绝对路径。

## 阈值速查

| 项 | 值 |
| --- | --- |
| 质询轮数 | ≤ 2（首轮 + 一次补版复审） |
| 每轮高洞 | ≤ 3 条，不堆弹幕 |
| 换岗触发 | 1 次，当前单生效 |
| 判词锁 | 无匹配 PASS verdict 时，真工程根 Write/Edit/NotebookEdit 全拦 |
| 免战语 | 「直接生成」只免反方开场，不免裁判与判词锁；「你看着办」非放行语 |

## 战报（work/reports/<slug>.md）

任务与架构要素表 / 反方质询清单（含**命中攻击库 `attacks/` 哪条**）与主攻方向 / 裁判判词（`PASS` 人类胜 or `FAIL` 人类败）+ 是否落 verdict / 是否换岗、**令追加到 `decrees/` 哪份**、罚单产物如何 / 豁免备注（免战 / 零豁免 / 无）。
