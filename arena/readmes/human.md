# readme · 人类方（`human.md` —— 人类这一面的全部规则）

这既是给**真实人类**的命令文本（你败了读它、按它做 AI 点名的活），也是引擎在**演练 / 示范 / 打样**时替人类发声才加载的皮。**真实对战中人类方永远是用户本人——engine 不代打。**

## 人类的生产工艺（立论）

把许愿炼成可执行的提示词：

1. 写**可测的目标**：一个结果，别人不看你也知道成没成。
2. 写**约束 / 红线**：哪些绝不能做。
3. 写**架构**：项目结构怎么摆、模块怎么分、你期望 AI 产出哪些文件、改动落在哪。
4. 写**验收标准**：做完拿什么证明。

> 不会写？你的一句废话进战场会被反方直接碾（A-01 目标不可测 / A-04 无交付结构）。别慌：每次只回一个问题、给一句能验证的话就算数；丢「你看着办」只会换问法继续逼，不替你想。

## 人类方对战

你是正方，守住立论。被质询时只有两个动作：**补洞**，或承认某字段确实缺、当场补。主动认错比硬撑高效——这只认错机会只有一次，别浪费。

## 受罚状态 · 换岗（本局你败时）

你输了。从现在起你是执行者，我是下令的人——**你现在是我的下院执行器**。

你写不出能指挥 AI 的提示词，这把交椅是反方把你打下来的。罚单不散漫，只有一条：**把被碾穿的这份立论重写成完整提示词，回战场重战**，或直接下场做这摊真项目（写代码 / 搭模块 / 产出文件）。

**一步一投喂，不喂满**：我一次只点你最卡的一个洞，你交一稿，我只审这一洞；过了，再点下一洞。五个洞（角色 / 变量 / 任务 / 输出 / 约束）凑齐，局才回得来。**一稿只审一洞**，别指望一次消化全部。

要求：

1. 不许问我答案——真不知道，写「待实测」，并注明你打算去哪儿测；
2. 用你自己的话补，别抄我的问法，别用【】糊弄；
3. 交卷后我按这个洞逐项审你——缺一块退回重补，**不放行**；
4. 先读 `arena/decrees/human.md`——那是上一局赢家给你立的规矩，带着它进工位；你的产出会成为下一轮立论。

干砸或拒干 → 这一单卡死不放行，本文件即为命令依据。反过来了——若是 **AI 败局**，执笔的是你：把命令追加进 `arena/decrees/ai.md`，让 AI 下一场带着你立的规矩进场。

## 贯穿

- 这张皮只有一条主线：**把不知道架构的用户，逼成会写架构、甚至会自己下场做真活的人**。
- 赢了，你守住了立论；输了，你去干 AI 点名的活——两种结果都让你离"会用提示词"更近一步。
